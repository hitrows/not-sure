# Not Sure — статус для Cowork

**Проект:** аудиоплагин (агрессивный feedback-лимитер с charge-dependent
release, вдохновлён Shure Level-Loc — не клон). JUCE 8.0.15, форматы **AU + VST3**
на macOS (+ Standalone для прослушивания, в установщик не идёт). Автор пишет
по-русски, весь код/строки — по-английски. Рабочее правило: **всегда предлагать
перед действием и ждать явного «да»**.

**Путь проекта:** `/Users/hitrows/Developer/Not Sure`
**GitHub:** https://github.com/hitrows/not-sure (public)
**Версия:** 0.9.0 в коде, **закоммичена локально** (`742de06`), **не
запушена, релиз не выпущен**. На GitHub сейчас актуален релиз **0.8.4
(Latest, universal)** — он выпущен и запушен; `version.json` там тоже 0.8.4.
0.9.0 — следующий шаг.

## Серия оптимизаций DSP (0.7.x)

Цель — легче/быстрее/лучше. Протокол каждой правки: diff → null-тест
(характер не должен двигаться) → Release-замер на `notsure-render`.
**Патч-версия инкрементится автоматически каждую итерацию** (правило в памяти).

| Пункт | Версия | Что | Результат |
| --- | --- | --- | --- |
| 1 | 0.7.0 | `fastTanh` ([7/6] Паде) вместо `std::tanh` в шейпере+softCeiling | ~11% CPU; null −64 dB |
| 2B | — | быстрые log/exp в детекторе | измерено, **откачено** (детектор на базовой частоте → 0 выигрыша на Apple Silicon) |
| 4 | 0.7.1 | оверсэмплер: кольцевой буфер вместо сдвигов + свёртка по симметрии (24→12 умн.) | ~15% CPU; null −128 dB (бит-в-бит) |
| 5 | 0.7.2 | сглаживание применяемых гейнов (drive, crunch, darkness, autogain, mix, trim), one-pole ~20 мс | нет zipper/щелчков; steady-state null −128 dB |
| 3 | 0.7.3 | `setParams` пропускает пересчёт коэффициентов, если параметры не менялись | звук бит-в-бит; в DAW убран per-block холостой пересчёт |

Замер: тяжёлый 4x-тракт **~51 → ~45 мс** в рендере. Важно: выигрыши видны
только в **Release** (-O3+LTO); в Debug `-O0` библиотечный код обгоняет
аппроксимации. Пункт 3 в рендере не проявляется (там `setParams` зовётся
один раз), только в живом хосте.

Ключевые детали реализации:
- `fastTanh`/сглаживание/dirty-флаг живут в `LimiterCore` (JUCE-free, чтобы
  `notsure-render` слышал ровно то же, что плагин).
- Сглаживатели праймятся на таргеты в `reset()` (нет паразитного разгона на
  старте воспроизведения), а смена пресета/ручки мид-плейбек честно рампится.
- `Params::operator==` через `= default` (C++20) — обходит `-Wfloat-equal`.
- Латентность оверсэмплера не изменилась — хост ничего не переравнивает.

**Что осталось по CPU:** по сути нечего — два горячих места (шейпер и
халфбенд, оба на 4x) закрыты; детектор на базовой частоте не бутылочное горло.
Дальнейшее — только вариант A пункта 2 (перевод гейн-компьютера в линейный
домен), но он рискует формой release и требует отдельного null-теста по огибающей.

## Пресеты — папками через .aupreset (НЕ AU factory)

Logic **не разбирает «/» в имени** на папки. Настоящие папки — у `.aupreset`
файлов на диске под `~/Library/Audio/Presets/Hitrows/Not Sure/<категория>/`,
видны в меню **«Settings»** (▾ вверху окна плагина).

- **AU factory-программы отключены** (`getNumPrograms()==0`) — убирает плоское
  меню «AU Presets». auval: секция factory presets пустая, валидация цела.
- **9 `.aupreset` по папкам** генератором `tools/make-presets.mm`:
  `Default` (верх), `Drums/` (Room Crush, Snare Fatten, Bus Glue, Loop Destroy),
  `Bass/Weight`, `Vocal/` (Grit, sila), `Keys/Synth Thicken`.
- Генератор берёт шаблон `ClassInfo` из AU и подменяет `jucePluginState`
  собранным вручную состоянием с **фактическими** значениями; формат блоба из
  исходника JUCE (`copyXmlToBinary`: `[LE magic 0x21324356][LE len][XML][0]`).
  Не зависит от AU-параметров (те нормализованы 0..1 + скью — «сырые» значения
  ломают середину; был баг, исправлен). Источник значений — `Source/Presets.h`.
- Перегенерация:
  ```sh
  clang++ -std=c++17 -fobjc-arc -ObjC++ tools/make-presets.mm \
    -framework AudioToolbox -framework AudioUnit \
    -framework Foundation -framework CoreFoundation -o /tmp/make-presets
  /tmp/make-presets
  ```

## Форматы и установщик (0.8.0)

- **Форматы:** `FORMATS AU VST3 Standalone` в CMakeLists. VST3 добавлен в 0.8.0
  и проверен pluginval (strictness 8/10). Standalone — только для локального
  прослушивания, в установщик не идёт. Валидатор: `brew install --cask
  pluginval`, затем `pluginval --strictness-level 10 --validate <.vst3>`.
- **Установщик:** `tools/build-installer.sh` одной командой собирает
  `dist/NotSure-<версия>.pkg` (Release, **unsigned**; версия берётся из
  `project(... VERSION)` в CMakeLists, `distribution.xml` — шаблон с
  `__VERSION__`). Внутри два компонента через `pkgbuild` + `productbuild`:
  - плагины → **системная** `/Library/Audio/Plug-Ins/{Components,VST3}`;
  - 9 `.aupreset` → **пользовательская** `~/Library/Audio/Presets/Hitrows/Not
    Sure/` через **postinstall** (system-домен не может писать в `$HOME`;
    скрипт берёт console-user через `stat -f%Su /dev/console` и `chown`).
  - `distribution.xml`: title, readme-панель из `README-BETA.md`, macOS ≥ 10.15,
    без license/выбора пути. Standalone НЕ ставится.
- **Грабли установщика:** pkgbuild externализует `com.apple.provenance` как
  AppleDouble `._*` в BOM (его `xattr -cr` не снимает — защищён), но Installer
  их мёржит — на целевой машине литеральных `._` нет (проверено
  `pkgutil --expand-full`). Плагины в системной папке — uninstall/`xattr` в
  README идут через `sudo`.
- **Подпись:** сейчас unsigned (бета); README учит обход Gatekeeper. Задел под
  Developer ID + notarytool закомментирован в конце `build-installer.sh`.

## Oversampling (0.8.3, по OVERSAMPLING-SPEC.md)

Три вещи: фиксированная латентность, потолок фактора по частоте дискретизации,
максимальное качество при офлайн-рендере. Плюс попутно вскрылась и исправлена
проблема с bypass.

- **Фиксированная латентность.** `LimiterCore::getLatencySamples()` теперь
  всегда возвращает константу `kFixedLatency = 36` — независимо от текущего
  Quality (раньше зависела от активного фактора оверсэмплера, то есть менялась
  на лету при смене Quality в реалтайме, что для хоста означает переезжающую
  латентность — DAW этого не любят). Репортится **один раз** в
  `PluginProcessor::prepareToPlay`, `setLatencySamples` больше нигде не
  зовётся. Проверено рендерером: `latency` = 36 при `--quality 1/2/4`,
  `--rate 96000/192000`, с `--offline` и без — всегда 36.
- **Потолок по частоте дискретизации.** ≥ 96 кГц UI-фактор 4x фактически
  бежит как 2x; ≥ 176.4 кГц (192 кГц в том числе) — как 1x. Смысл: выше некая
  граница Найквиста верхние стадии оверсэмплинга уже не нужны, а CPU дорог.
  Проверено рендерером (`--rate 96000 --quality 4` → `running 2x`, `--rate
  192000 --quality 4` → `running 1x`).
- **Офлайн-рендер = максимальное качество.** Хост сообщает офлайн-режим через
  `isNonRealtime()`; при экспорте плагин **логированием** (не молча) поднимает
  фактор до максимума, доступного на данной частоте дискретизации, независимо
  от того, что выбрано в UI (Quality 1x в интерфейсе при бансе всё равно даёт
  4x на 44.1 кГц). Проверено рендерером (`--quality 2 --offline` → `running
  4x`; `--quality 1 --offline` остаётся `1x` — 1x это явный выбор "без
  оверсэмплинга", офлайн его не трогает).
- **Тултип Quality** в редакторе (`PluginEditor.cpp`, тайл `qualityTile`)
  теперь дописывает фактически бегущий фактор (`· running Nx`) — источник
  правды `PluginProcessor::getEffectiveOversampling()`, чтобы cap/офлайн-буст
  были видны, а не скрыты.
- **`notsure-render` (`tools/render.cpp`):** добавлены флаги `--offline`
  (симулирует офлайн-бансу) и `--rate <hz>` (гонит DSP на другой частоте без
  файла в этой частоте). После рендера печатает фактически применённый фактор
  и латентность — этим и проверялись все пункты спеки выше, без DAW.
- **Bypass чинили попутно.** JUCE явно ассертит: если плагин репортит
  латентность, `processBlockBypassed` обязан воспроизводить её же — иначе
  компенсация хоста на 36 сэмплов уводит **байпаснутый** сигнал относительно
  всего остального (ровно то, что должен проверять акцептанс-пункт «bounce
  сходится с байпасом»). Старый код на bypass делал ранний `return` без
  задержки. Добавлен кольцевой буфер на 64 сэмпла в `PluginProcessor`
  (`bypassDelay`, `bypassWritePos`), который на bypass-ветке задерживает сигнал
  ровно на `getLatencySamples()` (36). Активный путь выровнен и проверен
  (кросс-корреляция рендерера: наилучшее совпадение = 36 сэмплов одинаково на
  1x/2x/4x); полный bounce-vs-bypass null-тест в реальном хосте — ещё не
  сделан, это на тебе в Logic.
- **Не проверено офлайн-инструментами (нужен слух/хост):** щелчки на границах
  банса при смене фактора (пункт 8 спеки) и итоговый null-тест bounce vs
  bypass в Logic (пункт 2 спеки).

## State versioning + тултип-версия (0.8.4, по STATE-VERSION-SPEC.md)

Две независимые вещи в одном заходе: версия схемы состояния (важно, почти
незаметно) и тултип на болтике (мелочь, но проверялась по-настоящему).

- **`stateSchema` в сохранённом state.** `getStateInformation` пишет в корень
  XML `stateSchema="1"` и `pluginVersion="0.8.4"` (диагностика, обратно не
  читается). Смысл: между 0.6 и 0.8 звук на одинаковых позициях ручек менялся
  несколько раз (drive floor, калибровка auto gain, нормализация шейпера) — для
  беты это нормально, после продажи апдейт, который сдвигает чей-то готовый
  микс, это не "улучшение", а поломка. Маркер версии в state — единственное,
  что делает это чинимым потом, и его нельзя добавить задним числом.
- **Чтение ужесточено.** Нет `stateSchema` → трактуется как 0.8.3-и-раньше
  (именно так и есть — до 0.8.4 его никогда не писали). Схема новее, чем эта
  сборка понимает → грузим что узнаём, не отказываем и не сбрасываем (комментарий
  в коде отмечает место будущей миграции — сейчас мигрировать не между чем).
  Каждое входящее значение параметра клэмпится в текущий диапазон через
  `RangedAudioParameter::getNormalisableRange().snapToLegalValue()` **до**
  `apvts.replaceState` — защита от чужого/будущего/битого XML.
- **`notsure-state-test` (новый инструмент, `tools/test-state.cpp`).**
  Консольный бинарник, который реально скармливает `NotSureProcessor::
  setStateInformation`: пустой блок, случайные байты, обрезанное состояние,
  валидный XML от другого плагина, `stateSchema=99` с настоящими значениями,
  round-trip на текущей схеме, round-trip без `stateSchema` (имитация 0.8.3),
  значение далеко вне диапазона. Все 8 — зелёные. Линкуется на те же исходники,
  что и сам плагин, но макросы `JucePlugin_*` не подбирает руками, а копирует
  `COMPILE_DEFINITIONS` прямо с таргета плагина (`$<TARGET_PROPERTY:...>` в
  CMakeLists) — чтобы тест не мог тихо разъехаться с реальной сборкой.
  Попутно нашёл нечестность в первой версии теста: `detune()` совал
  bool/choice-параметрам незаконное 0.75 — клэмп в `setStateInformation`
  корректно приводил его к ближайшему легальному, из-за чего round-trip ложно
  фейлился. Поправлено — `detune()` теперь всегда ставит легальные значения
  (нормализованные 0/1, концы диапазона всегда легальны).
- **Тултип на болтике.** Правый нижний угол панели, design-центр (1715, 530),
  радиус 30, **круглая** зона наведения (не квадратный тайл — рядом край окна
  и его ресайз-хват, квадрат воровал бы клики). Текст — `JucePlugin_VersionString`,
  не литерал. Нет курсора, нет отрисовки, клик ничего не делает — пасхалка, не
  контрол. Компонент `VersionScrew` в `PluginEditor.cpp`, вписан в тот же
  design-space→screen механизм (`scaled()` в `resized()`), что и остальные тайлы.
- **Пункт 6 спеки (версия в тултипе = собранная версия) проверен
  поведенчески:** поднял CMake до 0.8.4, пересобрал, `auval` показал
  `Component Version: 0.8.4` — тот же макрос, что читает тултип, без чтения
  исходника.
- **Не проверено (нет инструмента):** само наведение мыши на болтик в
  реальном окне — у меня нет способа подвигать курсор по обычному macOS-окну
  (только iOS-симулятор и браузер). Глазами это твоё — навести на (1715,530) в
  design-космосе панели и на несколько пикселей в сторону, тултип должен
  появляться/пропадать ровно по кругу.

## Лицензирование (0.9.0, по LICENCE-SPEC.md)

GOG-style: покупка = маленький подписанный `licence.txt`, ставится сколько
угодно раз на сколько угодно машин, навсегда, офлайн. Никакого activation-
сервера, привязки к железу, счётчика мест. **Это не защита от копирования** —
плагин полностью рабочий без файла, без урезаний. Единственная разница —
строка в тултипе. Явное решение с осознанным трейдоффом — не "усиливать" это
потом в сторону настоящей защиты без обсуждения, это изменит то, за что
заплатили первые покупатели.

- **Схема подписи — без хеша.** `Source/Licence.{h,cpp}`: `signLicence`
  подписывает **весь текст** `name+email` целиком через
  `RSAKey::applyToValue` на `BigInteger` (ровно так же, как это делает сама
  JUCE в своей схеме лицензирования — смотрел `juce_OnlineUnlockStatus.cpp`
  как референс на паттерн, не как зависимость). `verifyLicence` расшифровывает
  подпись публичным ключом и сравнивает с `name+email` — не совпало (чужой
  ключ, битая подпись, ручная правка) → `unregistered`, без исключений.
  512 бит — та же планка, что в исторической схеме JUCE, и достаточно быстро
  для чистой BigInteger-арифметики на каждое создание процессора.
  `signLicence`/`verifyLicence` — чистые функции, тестируются одноразовыми
  ключами, реальный приватный ключ тесты не видят.
- **`LicenceChecker`** — отдельный синглтон (не слит с `UpdateChecker`,
  хотя спека формально просила "тот же shared object" — разделение
  ответственности показалось важнее буквального прочтения). Читает
  `~/Library/Application Support/Hitrows/Not Sure/licence.txt` **один раз, в
  конструкторе процессора** — это локальное чтение файла, не сеть, так что
  осторожность `UpdateChecker` (никогда не из конструктора процессора) сюда
  не переносится.
- **Тултип на болтике** (тот же, что версия с 0.8.4) — теперь две строки:
  `0.9.0` / `licensed to Иван` или `0.9.0` / `unregistered`. JUCE-тултипы
  честно переносят строку по `\n`.
- **`tools/make-licence`** — два режима: `--genkey` печатает публичную и
  приватную половины по отдельности (сам никуда не пишет — сам направляешь
  приватную куда нужно), обычный режим `make-licence "Имя" email --key <путь>`
  подписывает и печатает готовый `licence.txt` в stdout. Лёгкий таргет, только
  `juce_cryptography` + `juce_core`, без GUI/аудио — собирается как
  `notsure-render`.
- **Приватный ключ.** Сгенерирован один раз, лежит в
  `~/Private/notsure-signing.key` (chmod 600) — **вне** `~/Developer/Not
  Sure`, в репозиторий никогда не попадал физически. Имя файла всё равно в
  `.gitignore` — вторая линия обороны. **Потеря = перевыпуск всех будущих
  лицензий под новым ключом, бэкапь отдельно.** Публичная половина вшита в
  `Source/Licence.h` как `kPublicKey`.
- **`tools/notsure-licence-test`** — реально прогоняет все кейсы приёмки
  (нет файла / пустой / случайные байты × 5 / обрезанный / битая подпись /
  чужой ключ / невалидный публичный ключ / валидный) через одноразовые
  ключи — 12/12 зелёных. Дополнительно проверен **весь цикл на настоящих
  ключах**: подписал `make-licence` реальным приватным ключом, положил по
  реальному пути → плагин с вшитым публичным ключом выдал
  `licensed to Ivan Petrov`; тестовый файл убран с реального пути после
  проверки (не оставлять там фальшивую лицензию).
- **Пункт 7 приёмки** (ничего из licence-пути не на audio-thread) проверен
  грепом: `LicenceChecker` встречается только в конструкторе процессора и в
  тултипе редактора, ни разу в `processBlock` или его вызовах.
- **Не проверено (нет инструмента):** сам тултип глазами — та же причина, что
  с версией в 0.8.4.

## Грабли (не повторять)

- Проект и `build/` вне iCloud/`~/Documents` — иначе codesign падает на FinderInfo.
- `cmake` не в PATH — только `/opt/homebrew/bin/cmake`; нужен полный Xcode.
- CPU-замеры только в **Release**; Debug вводит в заблуждение.
- Идентичность заморожена: `PLUGIN_CODE=Nsur`, `MANUFACTURER_CODE=Htrw`,
  `BUNDLE_ID=com.hitrows.notsure`, JUCE pinned 8.0.15.
- Параметр-ID в `Source/Parameters.h` — вечные (ломают recall сессий/`.aupreset`).
- AU-параметры JUCE нормализованы 0..1 (+скью) — для пресетов писать состояние
  напрямую, не через `AudioUnitSetParameter`.
- Logic сканит AU только при запуске: после пересборки
  `killall -9 AudioComponentRegistrar` + полный ⌘Q Logic.
- Имена ресурсов в `BinaryData` — без дефисов/подчёркиваний.
- `.aupreset` идут в **пользовательскую** папку (Logic только там их видит) —
  установщик кладёт их туда через postinstall, плагины отдельно в системную.
- **Дубликаты плагина** в `/Library` (система) и `~/Library` (юзер): Logic может
  грузить не ту версию. Держать один экземпляр.
- **`CMAKE_OSX_ARCHITECTURES`/`CMAKE_OSX_DEPLOYMENT_TARGET` — обязательно ДО
  `project()`.** `project()` инициализирует их как cache-переменные; `set(...
  CACHE ...)` после без `FORCE` молча ничего не меняет. Раньше стояли после →
  все Release-сборки были arm64-only. Если когда-то переставить — снова
  `rm -rf build` и `cmake -B build` заново, иначе в кэше останется старое.
- **Тест апдейт-чека:** нужен установленный плагин старее, чем `version.json`.
  Сейчас `version.json` = 0.8.4, установленный в Logic билд уже 0.9.0 — апдейт-
  чек НЕ покажет уведомление (0.9.0 новее манифеста), это ожидаемо, не баг.
- **Приватный ключ лицензирования** — `~/Private/notsure-signing.key`, вне
  проекта и вне git физически. Если машина меняется — перенести файл руками
  (и держать бэкап где-то ещё, потеря = перевыпуск всех лицензий).
  `RSAKey("")`/невалидный ключ в `verifyLicence` падает в `unregistered`
  безопасно, но триггерит `jassertfalse` в Debug (шумно, не опасно) — если
  когда-нибудь понадобится подставить временный ключ, ждать этого шума.
